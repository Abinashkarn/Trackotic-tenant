What to test

NOT IN MVP (removed from this canvas)
• Sites & locations — one site per tenant for now; HUB home site set from the device page
• Partners & visibility — received-from leg still shows as a summary automatically; no link management
• Integrations — Easysol import, API keys, webhooks, scheduled exports deferred
TEST · Sign in
• Password login (mobile or email)
• OTP login — SMS and email channel
• Wrong password ×5 → lock 15 min
• First login: set password, accept terms
• Forgot password → OTP → new password
• Office-bound role from outside allowed IP → blocked screen
• Field role from mobile data → allowed
• Session idle timeout → back to sign in
• Landing = Dashboard for every role; cards hidden by role
TEST · Monitoring
• Device list filters: type (HUB/Pro/Lite/Lite Pre), status, site, online/offline
• Last sync vs last recorded (offline buffer replay)
• Device detail graph: 24 h / 7 d, 2–8 °C band lines
• Alert raised within one telemetry cycle (90 s)
• Acknowledge alert with note → appears in audit
• Offline > 15 min alert; low battery; bag OPEN/CLOSE events
• Map shows only devices with GPS (Pro/Lite); HUB pinned to its site
TEST · Passports
• Passport QR batch generated by Track0tic appears as a print-ready file; tenant prints it (PDF / ZPL)
• Every print or reprint = audit event, never a new Passport QR
• One name everywhere: Passport QR, no unit/carton levels
• No device QR handling in the portal — devices arrive with QR on them
• Passport shows own legs + the one received-from leg only
• Bind to another device auto-releases previous binding
• Journey verdict: COMPLIANT / COMPLIANT WHERE MONITORED / EXCURSION
• PDF shows generation time while journey in progress
• Invoice ref optional (Easysol export)
TEST · Scan pages
• Device QR URL is an opaque token; login required before bind
• Scan 1…n passport QRs in one go; duplicates ignored
• Scan a passport bound elsewhere → shows previous custodian, binds anyway
• Public passport scan: no login, whole chain anonymised, no tenant names / TRK ids
• Leg with no device → "COMPLIANT WHERE MONITORED"
• Hindi toggle on public page
• Multi-chemist route: bind all 5 at warehouse; at each chemist scan device QR → Delivered → scan only that chemist's QRs (2, then 3); rest stay bound; journey shows stops
TEST · Users & roles
• Create user: mobile mandatory, email optional, role, site scope
• One role "Operator" for everyone who scans; Operator type (supplyman, collector, picker, dispatcher, delivery, warehouse, approver) is an editable label; approve-unlock is a per-user tick
• Office-bound toggle enforces IP allowlist on that user
• Deactivate user → active sessions ended
• Role matrix saves; viewer cannot see Users / Settings
• ~10 users (IVF firm) and ~10,000 users (large pharma): list paginates, search, bulk CSV import
TEST · Settings & reports
• Temperature profile per product class (2–8, 15–25, −20)
• IP allowlist CIDR add/remove → takes effect next login
• OTP channel default SMS, email optional
• Report generate → PDF/CSV; scheduled daily email
• Audit log append-only, filter by user / action / date, export

Not in MVP: Sites & locations, Partners & visibility, Integrations (Easysol import, API keys, webhooks). Nomenclature: one role "Operator" with an editable type; one name "Passport QR"; devices arrive from Track0tic with their QR already on them.
